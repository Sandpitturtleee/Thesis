Where is the Oracle?
Your function mark_state() is called by hand, with specific bitstrings. For Grover to find the minimum (or "values less than the candidate_min") dynamically, you need to mark indices according to a condition.
Currently:
# mark |1110>, |0010|, |1010|
mark_state("1110")
mark_state("0010")
mark_state("1010")
This is hardcoding the oracle.
How to Generalize the Oracle
You want something like:
For each possible index (state), check if arr[i] < candidate_min.
If yes, mark |i, a⟩ by flipping its sign.
So you would, instead of hardcoding, do:
arr = [value0, value1, value2, value3, ...]  # Your data
candidate_min = ...

# Loop over indices you want to mark
for idx, val in enumerate(arr):
    if val < candidate_min:
        bitstring = format(idx, '03b') + "0"  # ... or with the ancilla if you use it similarly
        mark_state(bitstring)
This way, your oracle marks all indices satisfying the condition, not just the ones you manually chose.
Your Oracle Function (in Code)
Here's how you could adapt your script for a 3-element list, 1 ancilla (for simplicity):
# Suppose arr stores the values at each index (size=8 for 3 qubits)
arr = [5, 8, 2, 4, 10, 7, 6, 3]
candidate_min = 8

def oracle_matrix_for_min(arr, candidate_min):
    N = len(arr)
    dim = N * 2  # include ancilla
    oracle_matrix = np.eye(dim)
    for idx, val in enumerate(arr):
        if val < candidate_min:
            # construct bitstring for index + ancilla (say ancilla=0)
            bitstring = format(idx, '03b') + "0"
            basis_idx = int(bitstring, 2)
            oracle_matrix[basis_idx, basis_idx] = -1
    return Qobj(oracle_matrix, dims=[[2] * 4, [2] * 4])

oracle = oracle_matrix_for_min(arr, candidate_min)
Now your oracle is generated automatically based on your data and condition.
Analogy
In real quantum: the oracle circuit uses quantum gates to compute and mark states dynamically.
In your QuTiP code: we simulate this by constructing the operator matrix in advance using our data and the comparison.
